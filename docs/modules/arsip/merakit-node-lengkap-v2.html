Merakit Node AirLens

Panduan langkah demi langkah dari nol untuk merakit node sensor AirLens: ESP32, sensor debu, tiga sensor gas, sensor suhu dan kelembapan, kartu microSD, dan kamera kejadian. Setiap komponen dirakit dan diuji satu per satu dulu, baru digabung. Tidak perlu pengalaman IoT.

0 dari 0 langkah selesai

    0Gambaran besar

    Node AirLens adalah kotak kecil berisi beberapa sensor yang dibaca oleh satu "otak", yaitu papan ESP32. ESP32 mengumpulkan angka dari semua sensor setiap menit, menyimpannya, dan saat ada kejadian (misalnya asap), membangunkan kamera untuk mengambil satu foto.

    Cara memakai modul ini

    Kerjakan berurutan. Setiap langkah punya diagram kabel, kode uji, contoh keluaran yang benar, dan daftar masalah umum. Centang Selesai di akhir langkah; centangnya tersimpan di browser ini. Bagian berlabel Hitungan (opsional) boleh dilewati.

    Alat

    • Multimeter digital (wajib): untuk mengecek tegangan sebelum menyambung sensor.
    • Laptop dengan Arduino IDE 2 (langkah 4).
    • Untuk tahap akhir (opsional): solder, timah, perfboard, obeng kecil, jangka sorong.

    2Dasar listrik yang perlu kamu tahu

    Lima ide ini cukup untuk seluruh modul.

    5 V dan 3,3 V

    Bayangkan tegangan seperti tekanan air. Sensor MQ, PMS5003, dan ESP32-CAM butuh "tekanan" 5 V. Tapi pin-pin ESP32 hanya tahan 3,3 V. Sinyal 5 V yang masuk langsung ke pin ESP32 bisa merusaknya.

    GND bersama

    GND adalah titik nol, "lantai" tempat semua tegangan diukur. Semua komponen harus berbagi GND yang sama. Kalau tidak, angka sensor akan kacau walaupun kabel lain benar.

    Arus dan daya

    Setiap komponen "minum" arus. Pemanas tiga sensor MQ saja sekitar 0,45 A. Ditambah komponen lain bisa melebihi 1 A saat kamera menyala, jadi kita pakai adaptor 5 V 3 A.

    Pin analog (ADC)

    Sensor MQ mengeluarkan tegangan yang naik turun mengikuti kadar gas. ESP32 mengubah tegangan itu menjadi angka lewat pin ADC. Kita pakai pin GPIO32, 34, dan 35 karena pin ADC lain tidak bisa dipakai saat WiFi menyala.

    Tiga "bahasa" sensor

    I2C (2 kabel: SDA, SCL) untuk BME280. UART (TX ke RX) untuk PMS5003. SPI (4 kabel) untuk modul microSD. Kamu tidak perlu paham isinya; cukup sambungkan pin yang tepat.

    Pembagi tegangan

    Dua resistor yang disusun seri "mengecilkan" tegangan. Dengan 10 kΩ di atas dan 20 kΩ di bawah, tegangan 5 V menjadi 3,33 V, aman untuk ESP32. Ini dipakai untuk ketiga sensor MQ.

    Hitungan (opsional): pembagi tegangan dan kebutuhan daya

    Pembagi tegangan. Tegangan keluar = tegangan masuk × R bawah ÷ (R atas + R bawah).

    Contoh: 5 V × 20 kΩ ÷ (10 kΩ + 20 kΩ) = 5 × 20 ÷ 30 = 3,33 V. Kalau sensor MQ mengeluarkan 2,4 V, yang sampai ke ESP32 adalah 2,4 × 0,667 = 1,6 V. Di kode, kita membalik hitungannya: 1,6 ÷ 0,667 = 2,4 V.

    Kebutuhan daya (perkiraan puncak).

    KomponenArus
    3 pemanas MQ (±150 mA masing-masing)450 mA
    ESP32 saat WiFi mengirim±250 mA
    ESP32-CAM saat memotret±300 mA
    PMS5003 (kipas)±100 mA
    BME280 + modul microSD±50 mA
    Total±1,15 A, jadi adaptor 3 A punya cadangan yang lega

    3Keselamatan

    Aturan wajib
    • Cabut daya setiap kali memindah kabel. Sambung dulu, cek, baru nyalakan.
    • Jangan pernah menyambung 5 V ke pin GPIO ESP32 atau ke pin 3V3.
    • Sensor MQ menjadi hangat (bisa ±50 °C) karena pemanas di dalamnya. Itu normal. Jangan diletakkan menempel di plastik tipis.
    • Periksa arah kapasitor elektrolit: kaki panjang (+) ke 5 V, sisi bergaris ke GND. Terbalik bisa meletus.
    • Kalau ada bau terbakar atau komponen sangat panas: cabut daya segera.
    • Jangan pernah membuat CO dengan sengaja untuk menguji MQ-7. Untuk menguji, cukup uap alkohol dari hand sanitizer.

    4Siapkan software di laptop

    1. Unduh dan pasang Arduino IDE 2 dari arduino.cc/en/software (versi Windows).
    2. Buka File → Preferences. Di kolom Additional boards manager URLs, tempel:
      https://espressif.github.io/arduino-esp32/package_esp32_index.json
    3. Buka Tools → Board → Boards Manager, cari esp32, pasang paket esp32 by Espressif Systems.
    4. Buka Tools → Manage Libraries, cari dan pasang Adafruit BME280 Library. Saat ditanya, pilih Install all agar library pendukungnya ikut terpasang.
    5. Colokkan ESP32 ke laptop. Kalau di Tools → Port tidak muncul port baru (misalnya COM3), pasang driver sesuai chip USB di papanmu: CP210x (Silicon Labs) atau CH340 (WCH). Tulisan kecil di chip dekat colokan USB memberi tahu jenisnya.
    Kenapa Arduino (C++), bukan Python?

    ESP32 bisa menjalankan MicroPython, tetapi dukungan kamera ESP32-CAM masih terbatas dan tutorial untuk pemula jauh lebih banyak dalam Arduino. Python tetap dipakai, yaitu di Raspberry Pi sebagai penampung data (bagian 17).

    5Langkah 1 · ESP32 hidup dan bisa "bicara"

    Belum ada kabel. Kita hanya memastikan ESP32, kabel USB, driver, dan Arduino IDE bekerja.

    1. Tancapkan ESP32 di tengah breadboard sehingga kedua baris pinnya berada di sisi berbeda dari celah tengah breadboard.
    2. Colokkan USB ke laptop. Di Arduino IDE pilih Tools → Board → esp32 → ESP32 Dev Module, lalu pilih port-nya.
    3. Tempel kode di bawah, klik Upload (panah kanan). Setelah selesai, buka Tools → Serial Monitor dan atur kecepatan ke 115200 baud.
    Arti setiap baris
    • Baris 1Komentar (diawali //), hanya catatan, tidak dijalankan.
    • Baris 2Memberi nama LED untuk angka 2, karena LED biru bawaan DevKit V1 tersambung ke GPIO2.
    • Baris 4–9setup() dijalankan sekali saat ESP32 menyala: pin LED dijadikan keluaran, Serial dibuka pada 115200 baud (kecepatan yang sama harus dipilih di Serial Monitor), lalu mencetak "ESP32 siap!".
    • Baris 11–18loop() diulang terus: LED dinyalakan (HIGH), tunggu 0,5 detik, dimatikan (LOW), tunggu lagi. Setiap perubahan dicetak ke Serial Monitor.

    Keluaran yang benar

    ESP32 siap! LED nyala LED mati LED nyala
    Kalau bermasalah
    • Port tidak muncul: kabel hanya untuk mengecas (ganti kabel data), atau driver belum terpasang.
    • "Failed to connect to ESP32": tahan tombol BOOT di papan saat tulisan Connecting… muncul, lepas setelah upload mulai.
    • Tulisan acak di Serial Monitor: kecepatan belum 115200 baud.

    6Langkah 2 · Jalur daya breadboard

    Breadboard punya dua pasang jalur panjang di tepinya (bertanda merah + dan biru −). Kita jadikan satu jalur 5 V dan satu jalur 3,3 V, dengan GND bersama.

    5 V3,3 VGND
    1. Hubungkan modul USB-C (dari adaptor 5 V 3 A) ke jalur atas: VBUS/5V → + dan GND → −.
    2. Pasang kapasitor 470–1000 µF di jalur atas: kaki panjang ke +, kaki bergaris ke −.
    3. Sambungkan pin 3V3 ESP32 ke + jalur bawah, dan pin GND ESP32 ke − jalur bawah.
    4. Sambungkan − jalur atas ke − jalur bawah dengan kabel hitam. Ini yang membuat GND bersama.
    5. Sambungkan pin VIN ESP32 ke + jalur atas (5 V). Sekarang ESP32 bisa hidup dari adaptor tanpa laptop.
    6. Nyalakan adaptor. Dengan multimeter (mode DC V), ukur jalur atas: harus 4,8–5,2 V. Jalur bawah: 3,2–3,4 V.
    Saat meng-upload kode lewat USB laptop

    Cabut kabel VIN dari jalur 5 V selama ESP32 tersambung ke laptop, supaya dua sumber 5 V tidak saling bertabrakan. Kabel GND tetap tersambung. Pasang lagi VIN setelah USB laptop dicabut.

    7Langkah 3 · Sensor suhu dan kelembapan BME280

    BME280 memakai "bahasa" I2C: dua kabel sinyal (SDA untuk data, SCL untuk detak), ditambah daya 3,3 V.

    Arti setiap baris
    • Baris 1–2Memakai library Wire (I2C bawaan) dan Adafruit_BME280 (yang dipasang di langkah 4).
    • Baris 4Membuat objek bme yang mewakili sensor.
    • Baris 8Memulai I2C pada GPIO21 (SDA) dan GPIO22 (SCL).
    • Baris 9–15Pemindai I2C: mencoba setiap alamat 1–126 dan mencetak alamat yang menjawab. BME280 biasanya di 0x76 atau 0x77.
    • Baris 16–19Mencoba menyalakan sensor di dua alamat itu. Kalau keduanya gagal, cetak pesan lalu berhenti di sini.
    • Baris 20Mencetak ID chip. BME280 asli = 0x60.
    • Baris 24–26Setiap 2 detik membaca suhu (°C), kelembapan (%), dan tekanan (Pa, dibagi 100 menjadi hPa). %.1f berarti satu angka di belakang koma.

    Keluaran yang benar

    Mencari perangkat I2C... Ditemukan di 0x76 Chip ID: 0x60 Suhu 29.4 C | Kelembapan 71.2 % | Tekanan 1008.6 hPa
    Kalau bermasalah
    • Tidak ada alamat yang ditemukan: SDA dan SCL tertukar, atau VCC/GND belum tersambung.
    • Ditemukan 0x76 tetapi "BME280 tidak ditemukan": kemungkinan besar sensormu BMP280 (tanpa kelembapan). Laporkan ke tim; sebagai ganti bisa pakai DHT22.
    • Kelembapan 0 atau 100 terus: sensor rusak atau palsu.

    8Langkah 4 · Sensor debu PMS5003

    PMS5003 butuh daya 5 V untuk kipasnya, tetapi sinyal datanya 3,3 V, jadi aman langsung ke ESP32. Ia mengirim angka lewat UART: kaki TX sensor ke kaki RX ESP32.

    Urutan pin konektor PMS5003

    Konektornya kecil (8 pin). Lihat tulisan di adaptor atau datasheet; urutan yang umum: 1 VCC (5 V), 2 GND, 3 SET, 4 RX, 5 TX, 6 RESET, 7–8 tidak dipakai. SET dan RESET boleh dibiarkan tidak tersambung.

    Arti setiap baris
    • Baris 1–2Memakai port UART ke-2 ESP32 dan menyiapkan wadah 32 byte, karena PMS5003 mengirim paket data sepanjang 32 byte.
    • Baris 6Membuka UART pada 9600 baud, RX di GPIO16 dan TX di GPIO17.
    • Baris 10–21Fungsi bacaFrame: mencari awal paket (byte 0x42 lalu 0x4D), membaca sisanya, lalu menjumlah 30 byte pertama dan membandingkannya dengan angka pemeriksa di 2 byte terakhir. Kalau sama, data utuh.
    • Baris 24–28Mengambil PM1.0, PM2.5, PM10 versi "atmosfer" dari byte 10–15. Setiap angka disimpan dalam 2 byte, digabung dengan (byte_tinggi << 8) | byte_rendah.

    Keluaran yang benar

    Menunggu PMS5003... (kipas harus berputar) PM1.0 9 | PM2.5 14 | PM10 17 ug/m3
    Coba

    Dekatkan dupa yang menyala atau tepuk debu di dekat lubang sensor. Angka PM2.5 harus naik dalam beberapa detik, lalu turun lagi.

    Kalau bermasalah
    • Kipas tidak berputar: VCC belum 5 V, atau GND lepas.
    • Kipas berputar tapi tidak ada angka: TX dan RX tertukar. TX sensor harus ke GPIO16 (RX2).
    • Angka 0 terus: tunggu 30 detik; sensor butuh waktu pemanasan.

    9Langkah 5 · Tiga sensor gas MQ

    Setiap modul MQ punya 4 pin: VCC (5 V), GND, AO (keluaran analog, yang kita pakai), dan DO (keluaran digital ambang batas, tidak dipakai). Karena AO bisa sampai 5 V, setiap AO melewati pembagi tegangan dulu sebelum masuk ESP32.

    SensorAO lewat pembagi keMendeteksi
    MQ-2GPIO34Asap, LPG, metana, H₂
    MQ-7GPIO35Karbon monoksida (CO)
    MQ-135GPIO32NH₃, NOx, benzena, CO₂
    Cek dulu dengan multimeter

    Sebelum kabel ke GPIO dipasang, nyalakan daya dan ukur titik tengah pembagi tegangan (antara 10 kΩ dan 20 kΩ). Tegangannya harus di bawah 3,3 V. Kalau lebih, resistornya tertukar.

    Arti setiap baris
    • Baris 1Nomor pin untuk ketiga sensor.
    • Baris 2Faktor pembagi tegangan: 20 ÷ (10 + 20) = 0,667.
    • Baris 3Resistor beban di modul MQ. Umumnya 1 kΩ (tertulis 102 di resistor kecil dekat pin). Kalau tertulis 103, isi 10.
    • Baris 6–13Fungsi bacaRs: membaca tegangan 20 kali lalu dirata-rata agar stabil, mengembalikan ke tegangan asli modul (dibagi 0,667), lalu menghitung Rs, hambatan sensor. Makin banyak gas, makin kecil Rs.
    • Baris 15–18Mengatur pin analog membaca rentang hingga ±3,1 V (ini juga bawaan ESP32).
    • Baris 19–23Setiap 2 detik mencetak Rs ketiga sensor dalam kΩ.

    Keluaran yang benar

    Rs MQ-2 18.3 kOhm | MQ-7 9.7 kOhm | MQ-135 24.1 kOhm

    Angka persisnya berbeda-beda di setiap sensor. Yang penting: angkanya stabil di udara bersih, dan turun saat ada gas.

    Coba

    Teteskan hand sanitizer di tisu dan dekatkan (jangan menempel) ke sensor. Rs MQ-135 dan MQ-2 harus turun cepat, lalu naik lagi setelah tisu dijauhkan.

    Hitungan (opsional): dari tegangan ke Rs

    Rs = RL × (5 V − Vout) ÷ Vout.

    Contoh: ESP32 membaca 1,20 V. Tegangan asli modul = 1,20 ÷ 0,667 = 1,80 V. Rs = 1 kΩ × (5 − 1,8) ÷ 1,8 = 1,78 kΩ.

    Kita tidak mengubah Rs menjadi ppm, karena kurva ppm di datasheet hanya akurat untuk gas murni di laboratorium. Yang dipakai model adalah Rs ÷ R0 (R0 = Rs di udara bersih, bagian 14).

    Batasan yang perlu diketahui

    Sensor MQ bereaksi terhadap banyak gas sekaligus, jadi tidak bisa memastikan gas mana yang paling banyak. MQ-7 idealnya dipanaskan bergantian (5 V lalu 1,4 V); modul biasa memanaskannya terus di 5 V, sehingga bacaan CO-nya bersifat indikatif saja.

    Kalau bermasalah
    • Rs selalu -1: kabel AO atau pembagi tegangan lepas.
    • Angka naik turun terus di awal: normal; MQ butuh pemanasan beberapa menit, dan stabil sepenuhnya setelah 24–48 jam pertama.
    • Rs sangat kecil (< 0,5 kΩ) di udara bersih: cek nilai RL di baris 3.

    10Langkah 6 · Penyimpanan microSD

    Modul microSD memakai "bahasa" SPI dengan 4 kabel sinyal. Kebanyakan modul punya pengatur tegangan sendiri, jadi diberi daya 5 V.

    1. Format kartu sebagai FAT32 di laptop (kartu 32 GB ke bawah).
    2. Pasang kabel sesuai diagram, masukkan kartu, upload kode.
    Arti setiap baris
    • Baris 1–2Library SPI dan SD bawaan ESP32.
    • Baris 3Pin CS (pemilih kartu) di GPIO5.
    • Baris 6–9Menyalakan kartu SD. Kalau gagal, cetak pesan dan berhenti.
    • Baris 10–11Membuka berkas /uji.csv dalam mode tambah. Kalau masih kosong, tulis baris judul kolom dulu.
    • Baris 12–14Menulis satu baris (waktu sejak menyala dalam milidetik + catatan), lalu menutup berkas agar tersimpan.

    Keluaran yang benar

    Berhasil menulis /uji.csv

    Cabut daya, pindahkan kartu ke laptop, dan buka uji.csv. Setiap kali ESP32 di-reset, satu baris baru bertambah.

    11Langkah 7 · Kamera kejadian ESP32-CAM

    ESP32-CAM adalah papan terpisah yang punya chip ESP32 sendiri. Ia tidur total dan hanya bangun saat pin GPIO13-nya menerima sinyal HIGH. Saat bangun, ia membuang beberapa foto awal (agar pencahayaan otomatisnya pas), menyimpan satu foto ke kartu microSD di papannya sendiri, lalu tidur lagi.

    Memprogram ESP32-CAM

    1. Masukkan kartu microSD (FAT32) ke slot di ESP32-CAM.
    2. Tancapkan ESP32-CAM ke papan ESP32-CAM-MB, lalu colokkan MB ke laptop dengan kabel USB.
    3. Di Arduino IDE pilih Tools → Board → esp32 → AI Thinker ESP32-CAM dan port-nya.
    4. Upload kode di bawah. Kalau muncul "Failed to connect": tahan tombol IO0 di papan MB, tekan sekali tombol RST di ESP32-CAM, lepas IO0, lalu upload lagi.
    5. Setelah upload, tekan RST sekali agar kode berjalan normal.
    Arti setiap baris
    • Baris 1–4Library kamera, sistem berkas, kartu SD bawaan kamera (SD_MMC), dan pengatur pin saat tidur.
    • Baris 6Pin pembangun: GPIO13.
    • Baris 7Penghitung nomor foto yang tetap tersimpan selama tidur (RTC_DATA_ATTR).
    • Baris 9–20Peta pin kamera untuk papan AI-Thinker (tetap, tinggal disalin), format JPEG, ukuran 800×600 (SVGA), kualitas 12 (makin kecil makin bagus).
    • Baris 22–28Fungsi tidur(): menahan GPIO13 di LOW dengan resistor internal, mengatur agar bangun saat GPIO13 HIGH, lalu tidur total.
    • Baris 31–34Kalau papan baru dinyalakan (bukan dibangunkan oleh pemicu), langsung tidur. Jadi foto hanya diambil saat ada kejadian.
    • Baris 35–36Menyalakan kamera; kalau gagal, tidur lagi.
    • Baris 37Membuang 3 foto pertama agar pencahayaan otomatis stabil.
    • Baris 38–46Mengambil satu foto, menyalakan kartu SD dalam mode 1-bit (agar GPIO13 tetap bebas), mencari nama berkas yang belum dipakai (kejadian_00000.jpg, dan seterusnya), lalu menyimpannya.
    • Baris 47–50Mengembalikan memori foto, menunggu sinyal pemicu turun ke LOW, lalu tidur lagi.

    Uji tanpa ESP32 utama

    1. Lepas ESP32-CAM dari papan MB. Beri daya dari jalur breadboard: pin 5V ke jalur 5 V, GND ke GND. Jangan dari pin 3V3 ESP32 utama, karena arusnya tidak cukup.
    2. Sentuhkan sebentar kabel dari jalur 3,3 V ke pin IO13 ESP32-CAM, lalu lepaskan.
    3. Ulangi 2–3 kali dengan jeda beberapa detik. Cabut daya, pindahkan kartu kamera ke laptop: harus ada berkas kejadian_00000.jpg dan seterusnya.
    Kalau bermasalah
    • "Brownout detector was triggered": daya kurang. Pastikan memakai jalur 5 V dari adaptor 3 A dan kapasitor terpasang.
    • Galat pin_sccb_sda saat kompilasi: paket esp32 di Arduino IDE terlalu lama; perbarui di Boards Manager.
    • Foto gelap atau hijau: normal untuk foto pertama di ruangan gelap; foto berikutnya membaik.
    • Kartu SD gagal: format ulang sebagai FAT32, coba kartu lain (8–32 GB).

    12Langkah 8 · Menghubungkan pemicu kamera

    Sekarang ESP32 utama yang membangunkan kamera. Satu kabel dari GPIO25 ESP32 utama, lewat resistor 1 kΩ, ke IO13 ESP32-CAM. GND keduanya sudah sama lewat jalur breadboard.

    Untuk uji, pemicu dijalankan dengan menekan tombol BOOT di ESP32 utama. Di firmware final, pemicunya adalah kenaikan tajam pada sensor MQ atau PM2.5.

    Arti setiap baris
    • Baris 1GPIO25 untuk pemicu; GPIO0 adalah tombol BOOT bawaan papan.
    • Baris 3–8Pemicu dijadikan keluaran dan dimulai dari LOW (kamera tetap tidur). Tombol dibaca dengan resistor internal (INPUT_PULLUP): terbaca LOW saat ditekan.
    • Baris 10–17Saat tombol ditekan: kirim HIGH selama 1 detik untuk membangunkan kamera, kembali ke LOW, lalu tunggu 5 detik agar satu tekanan hanya menghasilkan satu foto.

    Keluaran yang benar

    Tekan tombol BOOT untuk memicu kamera. Picu!

    14Pemanasan dan kalibrasi R0

    Sensor MQ baru perlu "dipanggang" dulu: dinyalakan terus selama 24–48 jam sebelum angkanya bisa dipercaya. Setelah itu kita mencatat R0, yaitu nilai Rs saat udaranya bersih. Semua bacaan berikutnya dibandingkan dengan R0.

    1. Biarkan node menyala 24–48 jam memakai kode uji langkah 5. Data selama masa ini tidak dipakai melatih model.
    2. Bawa node ke tempat berudara bersih (dekat jendela terbuka, jauh dari dapur, asap rokok, atau kendaraan) saat siang yang tidak berkabut.
    3. Catat Rs ketiga sensor setiap 2 detik selama 10 menit (biarkan Serial Monitor berjalan, lalu salin ke spreadsheet).
    4. Ambil nilai tengah (median) untuk setiap sensor. Itu R0-nya. Tulis di label kertas yang ditempel di node, dan catat di DECISIONS.md.
    5. Ulangi kalibrasi bila sensor diganti, atau bila monitoring menunjukkan angkanya bergeser.
    Hitungan (opsional): memakai R0

    Misalnya R0 MQ-2 = 18,0 kΩ. Saat ada asap, Rs turun menjadi 6,0 kΩ. Rasio Rs ÷ R0 = 6,0 ÷ 18,0 = 0,33.

    Rasio 1,0 berarti udara sama bersihnya dengan saat kalibrasi; makin kecil rasionya, makin banyak gas. Rasio inilah yang dipakai sebagai fitur model dan pemicu kamera.

    15Pindah ke perfboard dan masuk casing

    Breadboard cocok untuk uji, tetapi kabelnya mudah lepas. Untuk dipasang berminggu-minggu, rangkaian dipindah ke perfboard (papan berlubang yang disolder), lalu dimasukkan ke casing cetak 3D.

    1. Solder header perempuan (soket) di perfboard untuk ESP32, supaya ESP32 bisa dicabut tanpa membuka solderan.
    2. Buat dua jalur daya (5 V dan 3,3 V) dan satu jalur GND di perfboard, sama seperti breadboard. Pasang kapasitor di jalur 5 V.
    3. Solder ketiga pembagi tegangan MQ di perfboard, dekat pin GPIO34/35/32.
    4. Sambungkan sensor lewat kabel jumper male-female, beri label pada setiap kabel dengan selotip kertas.
    5. Ukur ulang semua tegangan dengan multimeter sebelum menyambung sensor, lalu jalankan lagi kode uji langkah 3–8 satu per satu.
    6. Masukkan ke casing sesuai urutan perakitan di dokumen v2 (bagian 14.7): sensor iklim di base, ESP32/ESP32-CAM/PMS5003/perfboard di sled core, modul MQ di rak ruang panas.
    7. Pastikan lensa ESP32-CAM tepat di belakang cincin lensa oranye, dan lubang kipas PMS5003 menghadap panel PMS.
    Belum pernah menyolder?

    Latihan dulu di sisa perfboard dengan beberapa kaki resistor. Solderan yang baik berbentuk kerucut kecil mengkilap. Kalau ragu, minta bantuan teman atau laboran; node tetap bisa didemokan di atas breadboard yang dirapikan.

    17Berikutnya: firmware final dan Raspberry Pi

    Kode di modul ini adalah kode uji per komponen. Firmware final menggabungkan semuanya dan dibuat terpisah setelah perangkat dari kampus pasti:

    • Membaca semua sensor setiap 60 detik, menghitung Rs ÷ R0, menambahkan waktu dari internet (NTP).
    • Mendeteksi kejadian (kenaikan tajam MQ atau PM2.5) dan memicu kamera, paling banyak satu foto per 5 menit.
    • Menyimpan ke microSD sebagai cadangan, dan mengirim ke penampung data lewat WiFi.

    Peran Raspberry Pi

    Raspberry Pi milikmu cocok menjadi penampung data yang menyala terus selama 3–4 minggu pengumpulan data sebelum pameran. Node mengirim data lewat WiFi, Pi menyimpannya dengan program kecil berbahasa Python. Ini menyelesaikan masalah "data dikirim ke mana" yang dibahas di dokumen v2 bagian 9.

    Yang perlu disiapkan

    Tipe Raspberry Pi (misalnya Pi 3 atau 4), kartu microSD untuk Pi, adaptor dayanya, dan jaringan WiFi yang bisa dipakai node dan Pi bersama. Setelah itu, kode penampung Python dan firmware final dibuat sebagai langkah berikutnya.
