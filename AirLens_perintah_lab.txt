LANGKAH 5 - (OPSIONAL) LM Studio untuk pembanding Qwen2.5-VL
---------------------------------------------------------------------
# Lewati kalau waktu sempit; evaluasi VLM akan berstatus "dilewati".
# Di Windows: LM Studio -> muat model Qwen2.5-VL -> tab Developer -> nyalakan server
# -> aktifkan "Serve on Local Network". Izinkan di Windows Firewall (port 1234).

# Alamat 1 (Docker Desktop):
docker run --rm curlimages/curl:8.11.1 -s -m 5 http://host.docker.internal:1234/v1/models
# Alamat 2 bila alamat 1 gagal (Docker Engine; IP gateway WSL):
GW=$(ip route show default | awk '{print $3}'); echo $GW
docker run --rm curlimages/curl:8.11.1 -s -m 5 http://$GW:1234/v1/models

# Isi alamat yang berhasil + "id" model VL persis seperti di keluaran:
nano .env
#   VLM_BASE_URL=http://host.docker.internal:1234/v1      (atau http://<GW>:1234/v1)
#   VLM_MODEL=<id model>
# VLM hanya dinilai pada 300 foto test (config/lab.yaml), jadi tidak memakan berjam-jam.

LANGKAH 6 - Cek lingkungan + kecepatan unduh Dhaka
---------------------------------------------------------------------
make setup-check PROFILE=lab
# Semua baris harus OK atau DILEWATI. GAGAL di baris GPU = pelatihan akan sangat lambat (CPU).

# Ukur kecepatan Zenodo (unduh 20 MB pertama dataset Dhaka, maks 60 detik):
curl -s -o /dev/null -r 0-20971519 -m 60 -w "%{speed_download}\n" "https://zenodo.org/records/7878371/files/dataset.rar?download=1" | awk '{printf "kecepatan %.2f MB/s -> Dhaka 4,5 GB kira-kira %.0f menit\n", $1/1048576, 4608/($1/1048576+1e-9)/60}'
# Kalau perkiraannya > 120 menit, pakai jalur DARURAT di LANGKAH 7 (tanpa Dhaka).

LANGKAH 7 - JALANKAN SEMUANYA (satu perintah)
---------------------------------------------------------------------
# Urutan otomatis: cek -> db+mlflow -> data -> latih -> evaluasi -> kemas hasil.
# Durasi tiap tahap dicatat di logs/lab_<waktu>_lab/timings.tsv.
# Kalau satu tahap gagal, tahap berikutnya dilewati, tetapi hasil yang sudah ada TETAP dikemas.
make lab-all PROFILE=lab

# --- JALUR DARURAT (pilih SATU, hanya bila perlu) ---
# a) Unduhan Dhaka terlalu lambat: jalankan tanpa Dhaka (tercatat di report.json):
#    AIRLENS_DATA_SOURCES=pm25vision,india_nepal make lab-all PROFILE=lab
# b) GPU GAGAL di setup-check tetapi tetap ingin jalan (CPU, sangat lambat):
#    SKIP_CHECK=1 make lab-all PROFILE=lab
# c) Hanya membuktikan alur dulu (cepat, 1 epoch; hasilnya BUKAN hasil akhir):
#    make lab-all PROFILE=lab SMOKE=1
#
# Kalau terhenti di tengah, ulangi perintah yang sama: unduhan Hugging Face dan Zenodo
# dilanjutkan dari posisi terakhir. Unduhan Kaggle dan pelatihan mulai dari awal.

KALAU ADA MASALAH
---------------------------------------------------------------------
"make: command not found"      -> sudo apt-get install -y make
permission denied saat docker  -> wsl --shutdown (PowerShell), buka Ubuntu lagi
GPU GAGAL di setup-check       -> jalur darurat b) atau c) di LANGKAH 7; catat di laporan
make data gagal India-Nepal    -> isi KAGGLE_* di .env, atau LANGKAH 4b
Unduhan Dhaka terlalu lama     -> Ctrl+C, lalu jalur darurat a) di LANGKAH 7
Disk penuh                     -> docker system df ; docker system prune
git push "Authentication failed" -> token salah/kedaluwarsa; pakai token, bukan password
git push ditolak (fetch first) -> git pull --rebase ; git push
Lihat log layanan              -> docker compose logs --tail=100 mlflow

Semua log ada di logs/ dan ikut di arsip hasil, jadi error apa pun bisa dianalisis di rumah.
